# جدول الدوام — دليل مبسّط للمبرمج

النسخة المفصّلة: [`duty-roster-programmer.md`](./duty-roster-programmer.md) وPDF في التنزيلات `NiroVera-duty-roster-programmer.pdf`.

مصدر الساعة في NiroVera. البصمة والتقويم والأجر يقرأون **الوردية المنشورة**، لا ساعة شركة افتراضية.

سلسلة المنتج: الجدول يخطّط → الحضور يلتقط → التقويم يثبت.  
هذا الملف للسلسلة الأولى فقط.

عزل البيانات: كل سجل تحت `companyId`. جدول واحد لكل `stationId`. لا تخلط فروعًا في شبكة واحدة.

---

## أين يعيش

| طبقة | مسار |
|---|---|
| سطح الإدارة / الموظف | `/app/shifts` (`lane=mine` أو `lane=manage`) |
| صفحة | `src/pages/Attendance.jsx` عند `pathname` ينتهي بـ `/shifts` |
| لوحة | `src/components/schedules/ShiftsPlatformBoard.jsx` → `ShiftWeekBoard.jsx` |
| اشتقاق ومنع النشر | `src/lib/shiftWeek.js` + `src/lib/shiftDerivations.js` |
| ليل 18632 | `src/lib/decision18632.js` |
| كتابة المتجر | `publishWeek` / `setEmployeeDayShift` في `src/lib/store.js` |
| حقيقة المجال | `ATTENDANCE_FACTS` → `attendance.schedule` في `src/lib/facts/attendance.js` |
| مخزن الشركة | `company.schedules[]` |

وجه الموظف (`mode="mine"`) للقراءة وطلب تغيير وردية.  
وجه الإدارة (`canEdit`) يرسم وينشر. صلاحية الرسم: مالك / مدير / عمليات + `canCreateTasks`.

جدول الموظف مقفول على فرع العمل (`employee.stationId` أو `profile.workStationId`). نطاق الهيدر «كل الفروع» فلتر عرض فقط — لا يستبدل فرع العمل.

## شكل البيانات

```js
{
  stationId: "st_…",
  shiftTypes: [
    { id: "morning", label: "صباحي", start: "07:00", end: "15:00", restMinutes: 30 }
  ],
  assignments: {
    "2026-10-05": { morning: ["emp_1"], evening: ["emp_2"] }
    // مفاتيح قديمة رقمية لأيام الأسبوع موجودة في المعاينة — فضّل المفتاح المؤرخ YYYY-MM-DD
  },
  publishedWeeks: { "2026-10-04": { at, by, validity, validUntil } },
  weekDirty: { "2026-10-04": true },
  nightCompensation: true
}
```

شخص واحد في وردية واحدة في اليوم. `assignEmployeeDayOnSchedule` يزيل المعرّف من كل الأنواع ثم يضعه في النوع الجديد أو راحة (`shiftTypeId = null`).

نوافذ قياسية: `STANDARD_SHIFT_WINDOWS` في `shiftDerivations.js`

| key | start–end |
|---|---|
| morning | 07:00–15:00 |
| evening | 15:00–23:00 |
| night | 23:00–07:00 |
| twelve | 07:00–19:00 (12 بقاء) |

## الصباح / المساء / الليل — ليس بعدد الساعات

التصنيف من **البداية** و**تقاطع نافذة الليل**، لا من أن اليوم 8 أو 9 ساعات.

```
isMorningShift   بداية 05:00–11:59 أو تسمية صباحي/morning
isEveningShift   بداية 12:00–22:59 أو تسمية مسائي/evening
performsNightWork  أي دقيقة في 23:00–06:00
isNightWorker      ≥ 3 ساعات داخل تلك النافذة (عامل ليلي)
```

مثال: `07:00–15:00` صباحي (8 ساعات).  
`07:00–16:00` صباحي أيضًا (9 ساعات — سقف م99 سياسة أجر، لا نوع وردية).  
`15:00–23:00` مسائي حتى لو طوله مساويًا للصباح.

التأخير يُقاس من `shift.start` لذلك الموظف، لا من 07:00 للشركة كلها.  
انظر `lateMinutesFromScheduledStart` و`getTodaysShift`.

## حالة الأسبوع (ساعة البصمة)

`weekPublishState(schedule, weekStart)`:

| kind | المعنى |
|---|---|
| `draft` | لم يُنشر — البصمة لا تُحسب وردية؛ تُعلَّم «بلا جدول» |
| `published` | في `publishedWeeks` وغير `weekDirty` |
| `edited` | نُشر ثم عُدّل — يحتاج إعادة نشر؛ لا أثر رجعي صامت |
| `implicit` | أسبوع ماضٍ بلا لقطة — يُعامل منشورًا |

`isWeekDayPublished` هو الحارس الذي يقرأه التقويم وكشف الموظف.

`publishWeek` يستدعي `checkWeekPublishGates` أولًا. إن `blocked` → لا كتابة. وإلا يضع لقطة الأسبوع ويمسح `weekDirty`.

تعديل تعيين أو نافذة وردية يضع `weekDirty[weekKey] = true`.

نسخ الشهر (`copyScheduleMonth`) ينسخ نمط التعيين فقط. لا يصفّر 18632 ولا ينشر الأسابيع.

## البوابات — امنع قبل النشر لا بعده

عند **ضغط الخلية**: `checkShiftChangeApplyGate`  
(إجازة طلباتي، عطلة م112، راحة ليلية 12س، حمل، لياقة طبية، موافقة بعد 13 أسبوع، حدث، سقف رمضان اليومي، تقليص ساعات الليل).

عند **زر النشر**: `checkWeekPublishGates`  
(48س أسبوع، 10س استثناء م106، 12س بقاء م101، راحة نصف ساعة كل 5س، راحة أسبوعية، رمضان 6/36، حظر شمس 3337، صِدام إجازة، حدث).

نقص تغطية الخلية = عبء جدولة، **ليس** غياب موظف. لا تسدّه بتمديد وردية قائمة.

لا تُعد رسم فحوص الأسبوع/18632 كلوحة كاملة داخل ملف الموظف. السطح هنا + `طلباتي`. الملف يحفظ الهوية واللياقة ويشير إلى الجدول.

## من يقرأ الجدول

| مستهلك | ماذا يأخذ |
|---|---|
| `getTodaysShift` | وردية اليوم من `assignments[dateKey]` لفرع الموظف (+ تغطية إضافية إن وُجدت) |
| بصمتي / كشفي | بداية/نهاية منشورة → حاضر / متأخر / غاب / بلا جدول |
| التقويم `/app/calendar` | نفس الأسبوع المنشور + إجازة معتمدة |
| طلباتي | إجازة تقفل الخلية؛ `shift_change` و`night_consent` يغيّران الإسناد لاحقًا |
| قسيمتي | ساعات عادية وإضافي مشتق (م107) — لا تُحرَّر على الشاشة كمصدر |
| الأداء | طول الفترة = مجموع الورديات المنشورة؛ **الحضور لا يدخل الدرجة** |

حقائق مشتقة: `attendance.overtimeHours` في `ATTENDANCE_FACTS` — `stored: false`.

## قواعد عند التعديل

1. لا تخترع ساعة دوام افتراضية للشركة. الساعة = الوردية المنشورة لذلك الشخص.  
2. لا تدمج الصباح والمساء لأن الطول تساوى (8 أو 9). قارن `start`/`end`.  
3. لا تنشر إن فشلت البوابة — أظهر `reason` المسمّى.  
4. لا تحسب غيابًا على إجازة معتمدة أو على خلية غير مغطاة.  
5. لا تخلط `stationId` جداول. محرّر فرع واحد في كل مرة.  
6. أرقام الشاشة مشتقة من `schedules` + الحضور المعتمد، ليست مصدرًا يُكتب يدويًا.

## اختبار سريع

1. أسند `07:00–15:00` — يجب أن يُصنَّف صباحيًا.  
2. أسند نفس الشخص `15:00–23:00` — التأخير من 15:00 لا من 07:00.  
3. اترك الأسبوع مسودة — البصمة «بلا جدول»، ليست `late`.  
4. انشر بعد تجاوز 48س — `PUBLISH_BLOCKED`.  
5. إجازة معتمدة على اليوم — الخلية مقفلة، `checkShiftChangeApplyGate` → `ON_LEAVE`.
